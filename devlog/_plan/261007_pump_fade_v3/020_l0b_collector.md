# L0b — isolated bounded public-data collector

Use existing `signalbot.capture` adapters and receipt/gap semantics plus `signalbot.pump_fade_v2.public_capture` normalizers/planners where their contract matches. Add a distinct v3 collector runtime; do not change recommender services, v2 policy/results, or production Discord/order paths. All-market inputs: censored `!forceOrder@arr`; `/fapi/v1/premiumIndex` every 60 s; `/fapi/v1/fundingInfo` every 5 min; `/fapi/v1/exchangeInfo` every 30 min; snapshot `!miniTicker@arr` once/min only if existing persistence cannot supply it. Event trigger: 24h return ≥20% and quote volume ≥2M USDT. For at most 25 active symbols and at most 26 h, capture bookTicker, markPrice@1s, depth5@500ms (or a proven bounded depth@500ms equivalent), and openInterest every 60 s. LRU eviction and all data gaps are explicit in manifests; every record has exchange and local receipt times.

Planned repository files: NEW `src/signalbot/pump_fade_v3/__init__.py`, `collector.py`, `config.py`, `disk_budget.py`; NEW `tests/unit/test_pump_fade_v3_collector.py`; NEW `config/pump_fade_v3/collector.json`; NEW `deploy/systemd/pump-fade-v3-collector.service`; NEW `docs/pump_fade_v3/COLLECTOR_RUNBOOK.md`. Reuse existing capture adapter interfaces; revise this manifest before code if their actual API requires a narrower path. No dependency changes.

Hard caps: systemd `MemoryMax=2G`, `CPUQuota=60%`, `Nice=10`, `IOWeight=50`, capped retry/backoff; dedicated data dir with 40 GB hard cap; compact/drop lowest-priority at 80%, stop writes and log alert at 95%, never delete unarchived terminal data. Enforce at most 25 event symbols and outbound public REST at ≤25% of the current 2,400 weight/minute IP budget (≤600/minute across collector tasks). At steady cadence the planned premium-index all-symbol call costs 10/minute, 25 event OI polls cost 25/minute, exchangeInfo averages <0.001/minute, and fundingInfo has weight 0 but shares a separate 500/5m/IP limit with fundingRate; capture actual response headers and account for recommender use before allowing requests. Honor `Retry-After`, exponential backoff, circuit breaker. No `!bookTicker`/depth all-symbol subscription. No service enable/deploy until L0 and staged gate both pass.

Tests: positive/negative/boundary event admission; 25/26th LRU eviction; 26h expiry; censored liquidation silence; receipt-vs-exchange timestamps; REST budgeting and 429/418 circuit behavior; 80/95% disk transitions; replay/idempotency/gap handling; unit disabled by default; assert production endpoints, order/Discord clients, shared DB are not reachable from the collector. After 24h staging, report compressed MB/day per stream; target <1.5 GB/day.
