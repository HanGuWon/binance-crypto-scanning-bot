# L0b — isolated bounded public-data collector

Use existing `signalbot.capture` adapters and receipt/gap semantics plus `signalbot.pump_fade_v2.public_capture` normalizers/planners where their contract matches. Add a distinct v3 collector runtime; do not change recommender services, v2 policy/results, or production Discord/order paths. All-market inputs: censored `!forceOrder@arr`; `/fapi/v1/premiumIndex` every 60 s; `/fapi/v1/fundingInfo` every 5 min; `/fapi/v1/exchangeInfo` every 30 min; snapshot `!miniTicker@arr` once/min only if existing persistence cannot supply it. Event trigger: 24h return ≥20% and quote volume ≥2M USDT. For at most 25 active symbols and at most 26 h, capture bookTicker, markPrice@1s, depth5@500ms (official USDⓈ-M partial-depth levels include 5 and document 500ms; 1000ms is not an advertised speed), and openInterest every 60 s. If the 24-hour compressed rate exceeds 2.0 GB/day, drop event-scoped depth entirely rather than issue an undocumented slower stream. LRU eviction and all data gaps are explicit in manifests; every record has exchange and local receipt times.

Planned repository files: NEW `src/signalbot/pump_fade_v3/__init__.py`, `collector.py`, `config.py`, `disk_budget.py`; NEW `tests/unit/test_pump_fade_v3_collector.py`; NEW `config/pump_fade_v3/collector.json`; NEW `deploy/systemd/pump-fade-v3-collector.service`; NEW `docs/pump_fade_v3/COLLECTOR_RUNBOOK.md`; NEW PC-side `scripts/oci_capture/pull_verified_segments.ps1`. Reuse existing capture adapter interfaces and v2d hash-acknowledged prune logic; revise this manifest before code if their actual API requires a narrower path. No dependency changes.

Hard caps: systemd `MemoryMax=2G`, `CPUQuota=60%`, `Nice=10`, `IOWeight=50`, capped retry/backoff; dedicated collector data directory on the DATA filesystem only (never root), hard cap 16 GiB, and data-filesystem free-space floor 12 GiB. When either cap/floor is reached, drop event-scoped depth first, then stop writes and log CRITICAL; never delete unarchived data. Keep newest 7 days on OCI. A PC-side pull script copies older segments to `D:\Binance-trade-analysis\oci-capture\`; it verifies hashes on readback before acknowledging/pruning the OCI copy via the existing v2d hash-acknowledged prune logic. The script is provided only; the user runs or schedules it. Target <1.5 GB/day compressed; if the 24h measurement exceeds 2.0 GB/day, drop event-scoped depth and report. Do not add/resize volumes. Official USDⓈ-M stream reference: https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/public (Partial Book Depth Streams; fetched 2026-10-08).

Enforce at most 25 event symbols and outbound public REST at ≤25% of the current 2,400 weight/minute IP budget (≤600/minute across collector tasks). Honor `Retry-After`, exponential backoff, circuit breaker. No `!bookTicker`/depth all-symbol subscription. Do not create OCI resources. Cost verification and seven-day reclaim telemetry are open user-verification items, not collector blockers. No service enable/deploy until the L0 A3 baseline is recorded and the staged gate passes.
