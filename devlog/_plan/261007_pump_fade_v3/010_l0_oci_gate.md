# L0 — OCI read-only capacity gate

No repository/config/service mutation. Read only the running OCI host's proc/sys/service telemetry and OCI tenancy metadata. Do not restart, reconfigure, load-test, or redeploy the recommender. Target identity must be independently confirmed before SSH. Measure continuously for at least 30 minutes; retain timestamped samples and a redacted receipt.

Record shape/architecture, tenancy Always Free totals, block-volume quota/use, egress allowance/usage, `nproc`, `free -m`, `df -h`, `uptime`, collector-relevant process RSS/CPU, recommender `runtime_heartbeats.max_loop_lag_ms`, WebSocket connections and observed REST weight/429/418 from existing logs. Do not print environment variables or credentials. Compare seven-day CPU/network/A1-memory telemetry to Oracle's current reclaim criteria; do not inject synthetic traffic.

Gate deliverable is a Korean status table in the final report. If access, identity, history, or any requested metric is unavailable, name it and leave L0 incomplete. Only a passing baseline permits a separately staged 2-hour collector test; promote only if recommender p99 lag delta ≤100 ms and still below warning threshold, RAM free ≥3 GB, load ≤1.6, and no new recommender 429/418. Otherwise stop/disable only the new collector and report; never tune the recommender.

Current official documentation snapshot (2026-10-07): Binance USDⓈ-M public endpoint info reports 2,400 request-weight/minute; General Info says IP-shared limits and 429 backoff/418 bans. Oracle's Always Free page says an A1 instance may be reclaimed after a 7-day window only when CPU p95 <20%, network <20%, and memory <20%. Exact active stream constraints and endpoint weights are checked in L0b before deployment.
